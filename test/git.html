Git 설명과 명령어

코드의 변경 내역을 기록하고 협업을 돕는 버전 관리 도구, Git을 알아봅니다.

Git이란?

Git은 파일의 변경 사항을 시간에 따라 기록하는 분산 버전 관리 시스템입니다. 이전 상태를 확인하거나 특정 시점으로 되돌릴 수 있고, 여러 사람이 각자 작업한 내용을 하나의 프로젝트에 합칠 수 있습니다.

Git은 내 컴퓨터에 저장되는 버전 기록을 관리합니다. GitHub 같은 서비스는 Git 저장소를 온라인에 보관하고 다른 사람과 공유할 수 있도록 도와줍니다.

기본 개념

  • 저장소(repository): 프로젝트 파일과 변경 기록을 보관하는 공간입니다.
  • 작업 디렉터리(working directory): 실제 파일을 열고 수정하는 공간입니다.
  • 스테이징 영역(staging area): 다음 커밋에 포함할 변경 사항을 골라 담는 공간입니다.
  • 커밋(commit): 선택한 변경 사항을 메시지와 함께 저장한 기록입니다.
  • 브랜치(branch): 기존 작업을 유지하면서 기능을 독립적으로 개발하는 작업 흐름입니다.
  • 원격 저장소(remote): GitHub 등 네트워크상의 저장소입니다.

일반적인 작업 흐름은 작업 디렉터리 → 스테이징 영역 → 로컬 저장소 → 원격 저장소입니다.

처음 설정하기

Git을 설치한 다음 이름과 이메일을 설정하면 커밋 작성자 정보로 사용됩니다.

git config --global user.name "이름"
git config --global user.email "이메일 주소"
git config --list

자주 사용하는 명령어

저장소 시작 및 복제

git init
git clone 저장소_URL

git init은 현재 폴더에서 새 저장소를 시작합니다. git clone은 원격 저장소를 내 컴퓨터에 복사합니다.

상태 확인 및 변경 내용 살펴보기

git status
git diff
git log --oneline

git status는 파일의 변경 상태를, git diff는 아직 스테이징하지 않은 변경 내용을, git log는 커밋 기록을 보여줍니다.

변경 사항 커밋하기

git add 파일명
git add .
git commit -m "변경 내용 설명"

git add로 커밋할 변경 사항을 스테이징 영역에 추가하고, git commit으로 기록합니다. git add .은 현재 폴더의 변경 사항을 추가하므로 커밋 전에 포함될 파일을 확인하세요.

브랜치 작업

git branch
git switch -c 새-브랜치
git switch 브랜치명
git merge 브랜치명

브랜치 목록을 확인하고, 새 브랜치를 만들거나 이동하며, 다른 브랜치의 변경 내용을 현재 브랜치에 병합합니다.

원격 저장소와 동기화

git remote -v
git pull
git push
git push -u origin 브랜치명

git pull은 원격 변경 내용을 가져와 현재 브랜치에 반영하고, git push는 내 커밋을 원격 저장소에 올립니다. 처음 올리는 브랜치에는 -u 옵션을 사용할 수 있습니다.

변경 취소하기

git restore 파일명
git restore --staged 파일명
git revert 커밋ID

git restore 파일명은 커밋하지 않은 파일 변경을 취소하고, git restore --staged 파일명은 스테이징만 해제합니다. git revert는 기존 기록을 보존하면서 특정 커밋의 변경을 되돌리는 새 커밋을 만듭니다.

주의: git reset --hard는 작업 내용을 삭제할 수 있습니다. 내용을 확인하고 백업하기 전에는 사용하지 마세요.

간단한 사용 예시

저장소를 복제하고 파일을 수정한 뒤 변경 내용을 기록하고 공유하는 흐름입니다.

git clone 저장소_URL
cd 저장소_폴더
# 파일 수정
git status
git add 수정한_파일
git commit -m "문서 업데이트"
git push

다른 사람의 변경 사항을 먼저 반영해야 할 때는 작업 전에 git pull을 실행하세요.

Git 명령어를 실행하기 전에 git status로 현재 상태를 확인하는 습관을 들여 보세요.
