Introduction to Information Technology · Chapter 06

컴퓨터 네트워크와 인터넷

네트워크가 기기를 연결하는 방식부터 웹 페이지가 인터넷을 통해 전달되는 과정까지 살펴봅니다.

IT개론 목차 핵심 정리와 생각해 보기
6.1 / NETWORK CONCEPTS

네트워크의 개념

컴퓨터 네트워크는 컴퓨터와 스마트폰, 서버, 주변 장치 등이 통신 매체와 규칙(프로토콜)을 이용해 데이터를 주고받을 수 있도록 연결한 시스템입니다. 네트워크를 통해 파일과 메시지를 전달하고, 다른 장치의 서비스와 자원을 이용할 수 있습니다.

장치 (노드)

네트워크에 연결되어 데이터를 보내거나 받는 컴퓨터, 서버, 스마트폰, 프린터 등의 장치입니다.

통신 매체

데이터가 이동하는 경로입니다. 유선 이더넷이나 광섬유, 무선 Wi-Fi와 이동통신 등이 있습니다.

프로토콜

장치들이 통신할 때 따르는 형식과 규칙입니다. 인터넷은 TCP/IP 계열의 프로토콜을 사용합니다.

네트워크에서 데이터는 목적지와 형식에 맞게 전달됩니다. 실제 통신은 여러 장비와 프로토콜이 역할을 나누어 수행하며, 한 종류의 장치나 규칙만으로 이루어지지 않습니다.

6.2 / LAN & WAN

LAN과 WAN

LAN과 WAN은 네트워크가 연결하는 범위와 구성 방식에 따라 구분할 때 사용하는 용어입니다. 경계가 항상 지리적 거리만으로 정해지는 것은 아니며, 관리 주체와 네트워크 구조도 함께 고려합니다.

구분 LAN WAN
의미 제한된 공간이나 조직 안의 장치들을 연결하는 네트워크 넓은 지역에 분산된 여러 네트워크를 연결하는 네트워크
예시 가정의 Wi-Fi, 학교 실습실 네트워크 도시·국가 간 통신망, 여러 지점의 사내 네트워크 연결
연결 장비의 예 스위치, 무선 액세스 포인트, 라우터 라우터, 통신 사업자의 전송망과 연결 장비

인터넷은 서로 다른 지역의 수많은 네트워크를 상호 연결한 전 세계 규모의 네트워크입니다.

6.3 / INTERNET & WEB

인터넷과 웹의 차이

인터넷(Internet)은 서로 연결된 네트워크들이 공통 프로토콜을 사용해 통신하는 기반 시설입니다. 웹(World Wide Web, WWW)은 인터넷을 통해 이용하는 서비스 중 하나로, 브라우저에서 웹 페이지와 여러 자료를 탐색할 수 있게 합니다.

인터넷

장치와 네트워크가 데이터를 교환하도록 연결하는 기반입니다. 웹 외에도 이메일, 파일 전송, 음성·영상 통신 등 다양한 서비스가 이용됩니다.

웹 (WWW)

웹 서버가 제공하는 자원을 URL로 식별하고, 브라우저가 HTTP 또는 HTTPS로 요청해 보여 주는 서비스입니다.

따라서 웹은 인터넷을 이용하지만, 인터넷의 모든 서비스가 웹인 것은 아닙니다.

6.4 / IP ADDRESS & DNS

IP 주소와 DNS

IP 주소는 IP 네트워크에서 데이터가 목적지를 찾고 장치나 네트워크 인터페이스를 식별하는 데 사용하는 주소입니다. IPv4는 점으로 구분한 네 부분으로 표현하고, IPv6는 더 넓은 주소 공간을 제공합니다.

IPv4 예: 192.0.2.25
IPv6 예: 2001:db8::25

위 주소는 문서와 예시에서 사용하는 예약된 주소 대역의 예입니다. 네트워크에서 사용하는 주소는 공인·사설 주소, 동적·고정 설정 등 여러 방식으로 관리될 수 있습니다.

DNS(Domain Name System)는 사람이 기억하기 쉬운 도메인 이름을 IP 주소 등 네트워크 정보와 연결해 찾도록 돕는 분산형 이름 시스템입니다.

브라우저에 도메인 입력→ DNS 조회→ 연결할 IP 주소 확인→ 서버와 통신

DNS 조회 결과는 네트워크와 캐시 상태에 따라 달라질 수 있으며, 도메인 이름과 IP 주소의 관계가 항상 일대일인 것은 아닙니다.

6.5 / HTTP & HTTPS

HTTP와 HTTPS

HTTP(Hypertext Transfer Protocol)는 웹 클라이언트와 서버가 요청과 응답을 주고받을 때 사용하는 응용 계층 프로토콜입니다. HTTPS는 HTTP 통신을 TLS로 보호해 전송 중인 데이터의 기밀성과 무결성을 높이고 서버 인증을 지원합니다.

항목 HTTP HTTPS
통신 웹 요청과 응답을 전달 TLS로 보호되는 연결 위에서 HTTP 요청과 응답을 전달
보호 기능 전송 내용을 암호화하지 않음 전송 중 암호화와 무결성 보호, 인증서 기반 서버 인증을 제공
주소 표기 http:// https://

HTTPS는 통신 경로를 보호하지만, 웹사이트 자체가 안전하거나 신뢰할 만하다는 뜻은 아닙니다. 사이트의 주소와 요청 내용을 확인하고 개인정보를 신중하게 입력해야 합니다.

6.6 / CLIENT & SERVER

클라이언트와 서버

클라이언트(Client)는 서비스나 데이터를 요청하는 프로그램 또는 장치이고, 서버(Server)는 요청을 받아 처리하고 응답이나 서비스를 제공하는 프로그램 또는 컴퓨터입니다. 역할을 가리키는 용어이므로 하나의 컴퓨터가 상황에 따라 클라이언트와 서버 역할을 모두 할 수도 있습니다.

클라이언트요청 → 서버 처리→ 응답 클라이언트에 결과 표시
  1. 사용자가 브라우저에 웹 주소를 입력합니다.
  2. 브라우저는 DNS를 이용해 서버와 통신할 주소를 확인합니다.
  3. 클라이언트가 HTTP 또는 HTTPS 요청을 서버에 보냅니다.
  4. 서버는 요청을 처리하고 상태 코드와 콘텐츠 등을 응답으로 전달합니다.
  5. 브라우저는 응답 내용을 해석해 페이지를 표시하고, 필요하면 추가 자료를 요청합니다.

웹 페이지에는 HTML 문서뿐 아니라 이미지, 스타일, 스크립트와 같은 여러 자원이 포함될 수 있습니다. 브라우저는 페이지를 표시하기 위해 이 자원들을 추가로 요청하기도 합니다.

6.7 / SUMMARY

핵심 정리

  1. 네트워크는 장치가 통신 매체와 프로토콜을 이용해 데이터를 주고받도록 연결한 시스템입니다.
  2. LAN은 제한된 공간이나 조직의 네트워크를, WAN은 넓은 지역의 네트워크 연결을 가리킵니다.
  3. 인터넷은 네트워크 기반이고, 웹은 인터넷에서 이용하는 여러 서비스 중 하나입니다.
  4. IP 주소는 네트워크에서 목적지를 찾는 데 쓰이며, DNS는 도메인 이름을 네트워크 정보와 연결합니다.
  5. HTTPS는 TLS로 HTTP 통신을 보호하며, 클라이언트는 요청하고 서버는 요청을 처리해 응답합니다.
